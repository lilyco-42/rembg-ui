# 商业化进度：2026-09-15

本轮交付的是浏览器商品图试用流程，尚不具备全面商业放行证据。

| 优先级 | 当前结果 | 剩余工作 |
|---|---|---|
| P0 批次/确认 | IndexedDB 恢复、冲突保护、修订确认绑定、清单追踪 | 真实设备多图压力测试、浏览器异常退出验收 |
| P0 内存 | 解码前文件头检查、16MP/8192 限制、条带扫描、64MiB ZIP | 移动设备内存压力及长时间连续批次 |
| P0 样本/授权 | 授权证据模板及试用验收步骤 | 收集可商用商品样本并逐项核验；没有虚构通过率 |
| P1 修边 | 擦除、恢复、会话撤销/重做、底稿与商品图共同回写 | 缩放、软笔刷、跨会话历史及更精细交互 |
| P1 规格 | 独立纯模块及测试 | 更多规格必须根据用户真实需求增加 |
| P1 工作台 | 原图对比、移动端单列、编辑弹窗 | 手机真机触控、工作台用户试用 |
| P2 经营 | 已确定“免费浏览器演示 + 创作者版 ¥29/月 + 小团队版 ¥99/月”的实验模型；加入套餐目录、签名授权和纯函数用量检查 | 价格仍需真实付费试单验证；收款主体、服务地域、退款方式确定后接支付与生产授权服务 |
| P3 扩张 | 暂不投入 | AI 场景、商城接入、团队、多语言需要需求证据 |

## 试用转付费的判断资料

每个有授权的商品样本记录自动结果是否可用、返修耗时、最后是否交付及失败原因。经营决策需要用户确认收款主体和经营方式；纯 GitHub Pages 的前端标记不能当作付费授权验证，不能以隐藏按钮模拟安全付费墙。

证据入口：`quality/sample-authorization-template.md`、`quality/trial-acceptance.md`。当前没有建立经过核验的商业样本集，质量放行仍为 unverified。

经营模型与技术边界见 `docs/commercial-model.md`。价格是实验假设，`commerce.py` 没有连接任何支付渠道；没有服务端密钥或令牌时，系统只返回受限试用。

## 多平台构建边界

| 入口 | 交付形式 | 当前定位 |
|---|---|---|
| Windows / Linux / macOS | Nuitka 桌面包 | 完整本地工作台和离线授权入口 |
| Android | 原生 APK（`arm64-v8a`、`armeabi-v7a`、`x86_64`）与 AAB | 端侧单图快速处理；模型按需下载，结果写入系统下载目录 |
| GitHub Pages | ONNX Runtime Web WASM + PWA | 免费浏览器演示与移动浏览器入口，首载后可缓存运行时/模型 |

Android 的 ABI 拆包、可选签名和构建命令记录在 [`android/README.md`](../android/README.md)。多平台“构建成功”不等于完成商业质量放行；Android 仍需真机耗时、峰值内存、相册分享和结果保存验收。

## 试用转付费的判断资料

每个有授权的商品样本记录自动结果是否可用、返修耗时、最后是否交付及失败原因。经营决策需要用户确认收款主体和经营方式；纯 GitHub Pages 的前端标记不能当作付费授权验证，不能以隐藏按钮模拟安全付费墙。

证据入口：`quality/sample-authorization-template.md`、`quality/trial-acceptance.md`。当前没有建立经过核验的商业样本集，质量放行仍为 unverified。

经营模型与技术边界见 `docs/commercial-model.md`。价格是实验假设，`commerce.py` 保持 provider-neutral；服务器上的 USDT/TRC20 通道属于试验部署。没有服务端密钥、公钥或令牌时，系统只返回受限试用。Ed25519 解决授权文件防篡改，不等于已经有完整支付、撤销账本或不可破解的桌面保护。

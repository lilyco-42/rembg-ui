# 商品图工作流：开发记录与后续验收

2026-09-12，本地首轮实现。目标是为商品摄影/卖家交付规格一致的图片，优先完善可用性，不添加账号与收费流程。

已完成：画布、主体居中、留白、白/灰/透明背景、PNG/JPEG/WebP、批次 SKU、唯一命名、UTF-8 ZIP、暂停续跑、失败重试、批次设置快照。抠图接口改为同步路由，由 FastAPI 在线程池执行，并串行调度推理，避免多标签同时推理放大内存。

自动验证：5 个 unittest 测试通过。覆盖主体像素位置、三种编码、透明背景限制、空主体、ZIP CRC/中文名；Node VM 执行实际页面工作流，验证暂停、保留成功项、失败重试与唯一文件名。

真实验证：浏览器上传仓库 test 目录的两张 JPG，使用本地 bria-rmbg CPU 模型，首张完成后暂停，第二张保持待处理。首张输出 1200×1200 PNG、白色角点。实际下载的 product-delivery.zip 解压与 CRC 检查通过，文件名 product_夏季商品_001.png。浏览器下载事件工具超时，但 Downloads 中的实际文件已独立验证。

HTTP 检查：非法画布、透明 JPEG、未知模型均返回 400；无启动 token 返回 401。

2026-09-13 增量：增加逐图确认、仅导出已确认项、包含全部任务的 delivery-manifest.json，以及 IndexedDB 本地批次保存。保存原文件、处理结果、规格与复核状态；恢复时将处理中项变为待处理。使用事务内版本比较阻止旧页面覆盖新页面的数据；连续保存仅在最新请求完成后显示已保存。

增量真实验证：本地 BRIA 完成一张商品图后，刷新及重开页面恢复成功；复核勾选与导出筛选刷新后保持。两个页面写同一批次时，旧页面提示冲突，刷新后保留新页面数据。实际下载 product-delivery (1).zip，CRC 通过，包含一张 1200×1200 白底 PNG 与清单；清单 reviewed/exported 均为 true。自动验证还覆盖复核筛选、清单内容和快照排除临时 URL。

范围限制：本轮未打包/发布安装包，未完成移动端专项验证；保存仅限同一浏览器及同一站点地址，清除站点数据会丢失，不替代项目备份；未实测存储配额耗尽或系统崩溃；SAM 修图仍走单图流程；未宣称 CPU 耗时达到商用吞吐指标，也未把模型自述当成商用授权证明。

下一阶段应沿同一主线验收：

1. 单图返修回写队列，保留原图与透明底稿，改规格无需重复 AI 推理。
2. 补充项目文件备份与导入，以及存储配额、异常退出和大批量恢复验证。
3. 面向普通用户的安装包和模型就绪检查，核验随附模型的商用条件，再确定分发方案。
4. 使用真实商品样本评估毛发、透明物体、白底白物体的返修率；记录 CPU/GPU 耗时和峰值内存。
5. 用户样批验证通过后，再考虑付费版功能、授权和自动更新。

# 浏览器批次质量验收清单

本清单用于验收 `web/` 浏览器入口的批次处理、恢复和交付。验收对象以实际构建产物和测试时的提交为准；每一项都要记录浏览器、设备、提交号、时间和证据路径。没有执行过的项标为 `未验证`，不能按预期行为推定为通过。

## 基线与范围

基线提交 `88646de` 的行为是：每批最多 10 张，逐图串行推理；输入为 PNG/JPEG/WebP，单张不超过 25 MB、总像素不超过 1600 万；页面显示原图、透明底稿和商品图，并提供逐图下载与 ZIP 下载；失败项显示错误，结果只存在内存中。刷新或开始新一批会丢弃本页结果，这是该历史基线的限制；2026-09-15 恢复版已经改变此行为，以 web/README.md 的增量验收为准。

IndexedDB 持久化场景标为“持久化目标”，只有在对应实现进入被测构建后才执行。目标是保存原文件、输出、规格和确认状态；刷新/重开时恢复已完成输出，把 `processing` 恢复为待处理；保存失败要可见；旧页面不能覆盖新页面的批次；清空队列要清除当前浏览器保存的批次。该目标不等于跨浏览器、跨站点或清除站点数据后的恢复保证。

本清单覆盖：

- 单图和 10 张批次的输入校验、串行处理、失败显示和再次处理；
- 刷新、关闭重开、异常中断后的恢复，以及待处理项重试；
- 两个页面同时修改时的版本冲突提示和数据不覆盖；
- 逐图复核、仅导出已确认项、逐图下载、ZIP 和任务清单；
- Worker/WASM 加载失败、超时、存储失败和打包失败时的可恢复性。

样本质量（主体完整、背景残留、边缘光晕、颜色和尺寸）必须由人工查看并在样本记录中填写。本清单不替代授权记录，也不允许用模型或仓库代码的许可证推断照片许可。

## 来源和测试准备

验收前核对以下来源：

| 来源 | 用途 |
| --- | --- |
| `web/app.mjs` | 当前输入限制、处理状态、失败提示、下载和 ZIP 行为 |
| `web/index.html` | 当前页面文案和“刷新会清空本页结果”的提示 |
| `web/README.md` | 浏览器支持范围、模型缓存和当前限制 |
| `docs/product-workflow-development.md` | IndexedDB 目标行为及历史验证记录；历史记录不能替代本次构建的实测 |
| `docs/handoffs/E01-quality.md` | 交付字段、样本许可和不伪造评价的要求 |

使用项目中已获授权或用户提供的本地样本。为测试文件校验、失败路径和空队列，可使用本地临时文件；不要从公开链接下载或转传图片。每次测试开始前清空浏览器站点数据会破坏恢复前置条件，因此只在专门的“新安装/无数据”用例中执行。

建议准备：1 张小于限制的 PNG、JPEG、WebP 各 1 张；1 个损坏或不支持的文件；超过 25 MB 的文件；超过 1600 万像素的文件；10 张以内的小批次；以及可在浏览器中打开的两个同源页面。大文件和样本只使用已授权本地文件。

每次运行在 `results-template.csv` 新增一行。耗时从浏览器可观察事件记录，无法精确测量时留空；不要填估计值。`review_outcome` 只能填写 `pass`、`fail`、`blocked` 或 `unverified`，并在 `notes` 中说明证据。

## 回归清单

### A. 当前浏览器入口

| ID | 场景和步骤 | 通过条件 |
| --- | --- | --- |
| A01 | 打开入口，选择 1 张合法 PNG；再以 10 张合法图片运行一批。 | 入口可用；每张出现原图和透明底稿，成功项出现商品图与两个逐图下载；状态显示完成数，处理按序进行。 |
| A02 | 依次加入不支持类型、超过 25 MB、超过 1600 万像素的文件，并与合法文件混合。 | 每个非法项单独显示明确失败原因；合法项仍可处理；没有把失败项计为完成或可导出。 |
| A03 | 在首张处理结束后观察队列，触发 Worker/WASM 加载失败或单图超时的测试环境。 | 失败消息可见；页面仍能下载已完成项；没有显示“全部完成”；重新选择合法文件并运行时不会复用损坏的 Worker 状态。 |
| A04 | 完成至少 1 张，检查原图、透明底稿、商品图的像素尺寸、格式和透明/白底角点。 | 文件可打开；透明底稿保留透明通道；商品图符合所选尺寸和背景；主体验收由人工记录，不能只凭文件存在判定质量通过。 |
| A05 | 勾选“已检查边缘”后分别切换“仅导出已确认图片”；尝试导出有成功、未确认、失败和待处理项的批次。 | 无可导出项时 ZIP 按钮禁用；筛选打开时只打包已确认成功项，关闭时打包全部成功项；失败/待处理项不打包图片。 |
| A06 | 下载逐图商品图、透明底稿和 ZIP；解压 ZIP 并检查 `delivery-manifest.json`。 | 文件名唯一且扩展名正确；商品图与透明底稿都在包内；清单包含全部任务、状态、复核和导出标记及失败原因；ZIP 可正常解压并通过 CRC 校验。 |
| A07 | 完成一批后开始新一轮处理，再刷新页面或关闭后重新打开。 | 按当前基线，旧结果会从页面消失且页面文案与此一致；该行为记录为已知限制，不得误报为持久化通过。 |
| A08 | 使用不支持 Worker、OffscreenCanvas 或 `createImageBitmap` 的浏览器/禁用能力环境。 | 输入控件被禁用并显示升级到新版 Chrome、Edge 或 Firefox 的提示；页面不进入假处理中状态。 |
| A09 | 在打包或浏览器下载失败的测试环境中点击 ZIP。 | 显示打包失败原因和逐图下载建议；已完成结果仍留在页面，允许恢复下载或再次打包。 |

### B. IndexedDB 持久化目标（实现进入被测构建后执行）

| ID | 场景和步骤 | 通过条件 |
| --- | --- | --- |
| P01 | 在同一浏览器、同一完整访问地址处理至少 2 张，等待“批次已保存”后刷新。 | 原文件名、输入文件、已完成输出、规格、确认状态和“仅导出已确认”设置恢复；可直接预览和导出已完成项。 |
| P02 | 让一张图完成，另一张处于 `processing` 或 `pending` 时刷新、关闭重开或模拟异常退出。 | 已完成图仍为完成并可导出；中断项恢复为待处理，不显示误报完成；点击“开始 / 继续 / 重试失败项”只继续未完成项。 |
| P03 | 让一项失败后刷新，再点击重试；同时保留另一项成功结果。 | 失败原因在恢复前可见；重试只处理失败/待处理项；成功项的输出和复核状态不被清空或重算。 |
| P04 | 打开同一地址的两个页面。页面 1 保存批次后，页面 2 在旧版本上修改并触发保存。 | 旧页面检测到版本不一致，停止自动保存并提示冲突；页面 1 的较新数据不被旧页面覆盖；刷新旧页面后显示较新批次。 |
| P05 | 在有保存批次时点击“清空队列”，等待保存完成，再刷新/重开。 | 页面队列为空，浏览器保存的当前批次也为空；不能因旧页面或延迟保存把已清空项目恢复回来。 |
| P06 | 模拟 IndexedDB 被禁用、打开失败、事务失败或配额不足。 | 页面明确提示本地恢复/保存不可用；不显示“批次已保存”；当前可见结果仍可逐图或 ZIP 下载；刷新后丢失风险在提示中可理解。 |
| P07 | 在恢复过程中刷新、关闭或打开第二页，观察加载状态和重复初始化。 | 恢复未完成前不允许清空、运行或导出造成竞态；恢复结束只渲染一次；异常能退出“正在恢复”状态并给出下载建议。 |
| P08 | 在一个页面导出后，另一页面改变复核状态并保存，再刷新第一个页面。 | 导出筛选和清单以最新保存版本为准；旧页面不会悄悄覆盖复核状态或导出设置；冲突提示可追溯到具体页面操作。 |

## 证据与判定

每个 ID 记录 `pass`、`fail`、`blocked` 或 `unverified`，附截图/录屏、控制台错误、下载文件名和清单内容路径。对于 A07 这类明确的当前限制，记录“行为符合当前基线”并保留限制说明；它不计为持久化通过。历史文档中的“真实验证”只作为线索，必须在当前构建上重跑 P01–P08 后才能宣称通过。

发布前最低门槛：A01–A06、A08–A09 通过；持久化实现进入发布构建时，P01–P06 必须通过，P07–P08 至少完成并无未解释的覆盖数据风险；所有失败项有可恢复路径，所有未验证项列在交付报告中。

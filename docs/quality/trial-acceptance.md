# 商品图商业试用验收步骤

本流程把“软件链路可运行”和“真实商品样本质量达到试用门槛”分开记录。没有取得并核验样本授权，最多可以验收界面、输入校验、恢复和 ZIP 等技术行为；不得宣称抠图质量、直接交付率或商业试用已经通过。

## 开始前的放行条件

1. 确认被测构建的提交号、入口 URL、模型名称和版本。记录浏览器版本、设备、操作系统、网络条件及是否首次加载。
2. 核对 `sample-authorization-template.md`。真实商品图只能来自 `permission_status=verified` 且 `local_path` 已存在的记录；候选链接、授权待确认文件和许可不明文件不进入试用批次。
3. 第一轮至少准备 5 条可追溯样本记录，覆盖白底白物、细毛/纤维、透明/反光和复杂背景。数量不足、类别缺失或任何一张未验证时，质量结论为 `unverified`。达到第一轮证据门槛后再扩展到 30 张。
4. 复制 `results-template.csv` 作为本轮结果表。没有实际运行的耗时留空，不填估计值；样本许可证据路径、输入文件路径和导出清单路径写在 `notes`。

## 试用执行顺序

### 1. 空数据和浏览器能力检查

在独立的测试配置中打开入口，确认 Worker、OffscreenCanvas 和 `createImageBitmap` 可用；记录首次加载和模型准备时间。再用一个本地临时损坏文件验证错误提示。此步骤只证明入口和错误路径，不形成样本质量结果。

### 2. 单张样本基线

从已验证授权样本中逐张选择文件，记录开始处理到结果可查看的 `infer_ms`。检查原图、透明底稿和商品图是否都能打开，确认输出尺寸、格式、透明通道/背景角点和唯一文件名。人工质量记录至少回答：

- 主体是否完整；
- 背景是否残留；
- 边缘是否有明显光晕或锯齿；
- 颜色、方向和尺寸是否符合交付规格；
- 结论是直接可用、需要返修还是失败，以及返修分钟数和原因。

在现有 `results-template.csv` 中，`review_outcome=pass` 表示直接可用；需要返修时使用 `review_outcome=fail` 并在 `notes` 以“需返修：”说明问题和修复结果；执行被阻断用 `blocked`；样本或授权证据不足用 `unverified`。不得把“文件成功下载”当作视觉质量通过。

### 3. 批次和交付

用不超过 10 张的已验证样本运行一批，确认串行进度、单项失败隔离和完成数。至少执行一次“仅导出已确认图片”和一次导出全部成功项：

- 未确认、失败和待处理项不应作为图片进入 ZIP；
- `delivery-manifest.json` 仍应列出全部任务、状态、复核和导出标记；
- 商品图和透明底稿文件名应唯一且能与样本记录对应；
- 解压并检查 ZIP CRC，保存 ZIP 和清单路径作为证据。

### 4. 恢复、中断和重试

在持久化版本中，等待“批次已保存”后刷新或重开，检查已完成输出、规格、确认状态和导出筛选是否恢复。让一项保持处理中并中断页面，确认它恢复为待处理；让一项失败后刷新并重试，确认已成功项不被重算或清空。旧页面同时写入时，确认出现冲突提示且旧数据不能覆盖新数据。存储打开失败、事务失败或配额不足时，确认不会显示“已保存”，且页面仍给出下载当前结果的路径。

### 5. 样本质量复核和统计

由人工逐张复核，不以模型名称、公开演示、仓库许可证或单张成功替代证据。按 `pass`（直接可用）、返修记录和失败记录统计：

```text
直接交付率 = 直接可用张数 / 已完成且有授权证据的样本张数
返修率 = 需要返修张数 / 已完成且有授权证据的样本张数
失败率 = 失败张数 / 已完成且有授权证据的样本张数
```

分母只包含实际处理且授权状态为 `verified` 的样本；候选、未收集和未验证样本不能放入分母。返修分钟数按实际人工计时填写，无法测量则留空并在 `notes` 说明。

## 结论门槛

| 结论 | 必备证据 | 允许的表述 |
| --- | --- | --- |
| 技术链路通过 | 当前构建完成入口、输入校验、批次、导出、恢复/冲突相关用例；每项有结果和证据 | “该构建的浏览器工作流已按列出的场景验证” |
| 样本质量可评估 | 至少 5 张 `verified` 样本，覆盖目标类别；每张有人工作品观察和结果记录 | “在这批有授权样本上观察到……” |
| 商业试用质量通过 | 样本质量可评估，所有阻断项已解释，真实目标设备和交付链路完成；门槛由用户事先确定并记录 | 只能按事先约定的范围和设备描述结果 |
| 未验证/阻断 | 没有授权样本、样本未收集、证据缺失、关键场景未执行或设备不匹配 | 只能说明缺口，不能宣称商业质量或直接交付率 |

即使软件技术用例全部通过，若 `sample-register.csv` 尚不存在、样本仍为 `pending`/`unclear`/`not_collected`，本轮“商品样本质量”和“商业试用”仍为 `unverified`。不要把已有的建筑/人像、合成图片、单张公网演示或历史文档记录冒充本轮真实商品样本证据。

## 交付包

提交试用结论时一并保留：被测提交号和环境、`sample-register.csv`、授权证据卡、填写后的结果 CSV、人工复核备注、失败/恢复证据、导出的 ZIP 与 `delivery-manifest.json`。删除或撤回授权后，重新标记受影响样本并重新计算统计，不沿用旧的“通过”结论。

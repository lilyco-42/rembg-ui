# Rembg Studio 离线积分计费与许可证审计（2026-10-28）

## 定价与扣费定义

目标：成功生成并交付一张输出图 = **1 积分**，处理失败或用户取消且尚未成功交付 = **0 积分**。重复请求必须使用同一个后端生成的 job_id，不能重复扣费；用户再次主动发起的新任务则是另一笔 1 积分。批处理按实际成功输出的张数计算，不因 ZIP 导出再次扣费。

积分≠人民币，兑换比率、退款政策、开票与支付渠道需单独公布，不能默认援引 LYCO 其他服务的积分兑换率。离线预付模式只能消费服务端确认付款后签发的积分包，**不可在客户端签名或生成充值额度**。

## 上游许可证与许可边界

- [rembg 软件库](https://github.com/danielgatis/rembg/blob/main/LICENSE.txt)：MIT，允许商业使用，但应保留版权许可声明。
- [BRIA RMBG-2.0](https://huggingface.co/briaai/RMBG-2.0)：CC BY-NC 4.0，非商业；**没有 BRIA 书面商业授权时，必须禁止它进入收费处理路径，也不应把其模型权重打包用于付费销售**。
- 其他 U2Net、ISNet、BiRefNet、SAM 等：需逐一核对对应具体模型权重、训练/再分发许可（而非只看 Python 源码的 MIT 许可）。未核实者默认不得作为收费模型发布。
- WebGPU ONNX Runtime Web 的包许可证、模型权重和第三方依赖公告应在最终安装包中列出；目前仍需发行前第三方依赖完整清单审计。

## 已实现的离线预付积分包核心（未启用到产品收费）

`offline_points.py` 支持：
1. Ed25519 公钥验签的 `pc1` 积分包；签发私钥只能留在可信服务端。
2. 固定设备哈希、签发/过期时间、积分数量、唯一充值包 ID；本机相同充值包只能激活一次。
3. SQLite 单事务 `BEGIN IMMEDIATE` 预留、成功确认、失败退款；每次成功完成扣 **1** 积分；任务 ID 幂等。
4. 账本不保存用户图片，仅记录积分包和任务状态。

测试：`python -m unittest discover -s tests -p test_offline_points.py -v`。

**安全限制（重要）**：用户拥有本地设备和 SQLite 文件时，可以备份、替换、复制、回滚本地数据。系统时钟也可回拨。即使签名积分包有效，**纯离线本地计数无法从数学上保证防无限重放或余额回滚**。本机账本适合作为受限离线额度/预付演示，不是绝对安全的钱包。

## 阻断上线的未完成工作

- 目前的 `main.py` 仍是“月度用量配额”体系；**这次没有切换真实扣费**，不得标注“已上线每图 1 积分”。要实现真实业务必须在本地成功交付的所有服务端处理路径接入 reserve/complete/refund，确保 HTTP/超时/并发都按同一个 job_id 审计。
- WebGPU 由浏览器直接推理，绕过 Python 接口；浏览器 JS 变量、token 或前端按钮不能当收费防线。上线前必须采用有服务器强制验收的执行路径、可信离线硬件/安全执行环境，或明确转为**有限防篡改的离线许可**。完全离线、用户完全掌控的客户端不能获得与在线服务端同等级的不可绕过计费保障。
- 充值发包服务须连接实际支付回调，验证订单、拒绝重放并审计签发日志，切勿在 App 内嵌入私钥。
- 需定义争议退款、成功交付判据、额度展示、授权迁移/设备损坏补偿、用户协议/隐私政策，以及账户与支付相关法规审查。
- 需要对所有收费模型作许可白名单审计，默认阻止 BRIA RMBG-2.0 和其他未确认模型。
- 对并发下重复 job_id、进程崩溃后的 reserved 状态、设备数据恢复与跨设备重复消费做完整端到端测试。

**结论：许可审计发现 BRIA 商用限制；独立离线积分核算原型及单元测试已完成；生产收费未启用。**
